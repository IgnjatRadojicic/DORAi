# Decisions

One line each: date, who, decision, why. Newest at the bottom.

- 2026-11-21, team: Desktop and Android clients only, both with Compose Multiplatform. Why: one UI codebase, the two platforms the firms asked for.
- 2026-11-21, team: Server on Ktor with Exposed, PostgreSQL with pgvector, Flyway migrations. Why: Kotlin end to end, one database for register and regulation search.
- 2026-11-21, team: AI through Koog. Why: Kotlin-native agents and tool calling.
- 2026-11-21, team: Self-hosted server; invite link carries server address, one-time code and certificate fingerprint, never a password. Why: firms keep data on their own infrastructure; pinning makes self-signed certificates safe.
- 2026-11-21, team: Admin sets a temporary password that must be changed at first login; roles admin, reviewer, viewer. Why: simple, no external identity provider needed.
- 2026-11-21, Ignjat: Rules, validator and Terraform plan reader live in `shared` (`dorai.shared.rules`). Why: server and CLI must produce identical findings.
- 2026-11-21, Ignjat: compileSdk 37 (Compose 1.12 requires it), targetSdk 36, minSdk 26. Why: library requirement; target stays on the stable runtime behaviour.
- 2026-11-21, Ignjat: Contract keeps the established field names and JSON values; Kotlin types drop any suffix (`Finding`, `Resource`). Why: fixtures parse as they are and every lane works from the same shapes.
- 2026-11-21, Ignjat: Dates use `kotlinx-datetime` (`LocalDate`) and `kotlin.time.Instant`; money is `Double`, the server rounds to 2 decimals before sending. Why: plain JSON numbers, and `BigDecimal` is not available in common code.
- 2026-11-21, Ignjat: `DoraiApi` returns a sealed `ApiResult` (success or problem details) and never throws for HTTP or network errors. Why: screens must handle the error case explicitly.
- 2026-11-21, Ignjat: Phase 1 server serves the FinPay demo data (a fictional firm) from `server/src/main/resources/fixtures`; suggestions are decided in memory. Why: the apps and AI can start before the database exists.
- 2026-11-21, Ignjat: Password hashing with password4j (Argon2id). Why: pure Java, sane defaults, no native library to ship.
- 2026-11-21, Ignjat: AWS collectors use the AWS SDK for Kotlin. Why: coroutine-native, fits Ktor and Koog.
- 2026-11-21, Ignjat: Exposed DSL only, no DAO. Why: fewer moving parts.
- 2026-11-21, Ignjat: PDF report with OpenPDF. Why: high-level tables and paragraphs make the register report short to write.
- 2026-11-21, Ignjat: EBA CSV written with Apache Commons CSV. Why: correct quoting of commas and line breaks without custom code.
- 2026-11-21, Ignjat: App navigation with JetBrains Navigation Compose. Why: official multiplatform port, type-safe routes, per-screen ViewModels.
- 2026-11-21, Ignjat: App settings in DataStore Preferences; tokens encrypted with Android Keystore on Android and kept in the OS keychain (java-keyring) on desktop. Why: tokens stay secret at rest.
- 2026-11-21, Ignjat: File dialogs with FileKit. Why: one Compose API for desktop and Android, no platform code.
- 2026-11-21, Ignjat: Server generates a self-signed TLS keystore on first start (ktor-network-tls-certificates) unless one is configured. Why: zero setup for firms and the demo; the fingerprint goes in the invite link.
- 2026-11-21, Ignjat: ViewModel and Flow tests use Turbine. Why: short, readable assertions on StateFlow emissions.
- 2026-11-21, Ignjat: Service interfaces live in `dorai.server.core` (collectors, cost, repositories, AI, exporter) and `dorai.shared.rules` (plan checker, validator); routes call only these. Why: each lane replaces a fixture or fake behind an interface without touching routes or other lanes.
- 2026-11-21, Ignjat: Wiring by hand through one `Services` data class, no DI framework. Why: a dozen dependencies don't need a container, and tests swap one piece with `copy`.
- 2026-11-21, Ignjat: AI services return `AiAnswer` (answer with at least one citation, insufficient evidence, or failed). Why: the type itself enforces the cite-or-say-so rule.
- 2026-11-21, Ignjat: Firms run the server with Docker Compose (`deploy/`); CI publishes the image to GHCR on version tags for amd64 and arm64. Why: firms pull a tagged image and need no source or JDK.
- 2026-11-21, Ignjat: Server image based on eclipse-temurin:21-jre. Why: official, patched, has a shell for debugging and the health check.
- 2026-11-21, Ignjat: The server terminates TLS itself on 8443 with the keystore in a Docker volume; plain HTTP only on the host. Why: the pinned fingerprint is exactly the server's, no proxy to configure.
- 2026-11-21, Ignjat: A compose backup service runs pg_dump nightly and keeps 14 days. Why: backups happen by default; firms copy the folder offsite.
- 2026-11-21, Ignjat: Each register field stores its provenance in sibling columns (`<field>_label`, `_updated_at`, `_citation` jsonb, `_reason`). Why: plain SQL can filter by provenance, e.g. every AI-suggested value.
- 2026-11-21, Ignjat: The server uses PostgreSQL only when `DORAI_DB_URL` is set, otherwise fixtures in memory. Why: tests and quick local runs need no database; compose sets the variable.
- 2026-11-21, Ignjat: The FinPay demo register is seeded on start only when no register is stored. Why: the demo works on a fresh install and a firm's own register is never touched.
- 2026-11-21, Ignjat: Database tests run on Testcontainers with the compose image `pgvector/pgvector:0.8.7-pg16`. Why: they test the same database as production, jsonb and pgvector included.
- 2026-11-21, Ignjat: The Azure live scan reads every subscription the credential can read, with optional `DORAI_AZURE_SUBSCRIPTIONS` and `DORAI_AZURE_RESOURCE_GROUP` filters. Why: the firm's Reader role decides the scope.
- 2026-11-21, Ignjat: Real AWS is scanned with the Resource Groups Tagging API and costed with Cost Explorer per resource (last 14 days). Why: no setup at the firm; the limits (never-tagged resources, 14 days, USD 0.01 per call) are documented in docs/deploy.md.
- 2026-11-21, Ignjat: For the demo, AWS runs on LocalStack (`DORAI_AWS_ENDPOINT`): S3, DynamoDB, Lambda and SQS listed one by one, AWS cost from the FinPay fixture, cost source Mixed. Why: free LocalStack returns nothing from the Tagging API and has no billing.
- 2026-11-21, Ignjat: Live cost is converted to `DORAI_COST_CURRENCY` (default EUR) with fixed `DORAI_FX_<CODE>` rates; rows without a rate are left out. Why: concentration adds amounts, so they must share one currency; fixed rates keep it offline and predictable.
- 2026-11-21, David: Regulation PDFs are read with Apache PDFBox 3. Why: standard JVM library, Apache 2.0, line-ordered text is enough for chunking.
- 2026-11-21, David: Regulation chunks follow the document structure: recitals, article paragraphs, Annex I template columns (B_xx.xx.nnnn) and Annex III service types (S01 to S19). Why: every citation must name a real article or paragraph, and the classifier needs one chunk per service type.
- 2026-11-21, David: Regulation chunks are stored only in PostgreSQL with pgvector; no in-memory store. Ingestion and search wait for the database setup. Why: one implementation, the same one the demo runs.
- 2026-11-21, David: Embeddings use `text-embedding-3-small` (1536 dimensions) through Koog, key from `DORAI_AI_*`; search keeps chunks with cosine similarity of at least 0.40. Why: 0.40 is the measured threshold for this model; higher values rejected clearly relevant chunks.
- 2026-11-21, David: Regulation chunks live in table `regulation_chunks` (migration V2, pgvector `vector(1536)`, HNSW cosine index). The stored hash is SHA-256 of embedding model id plus chunk text; ingestion is a sync that deletes rows the corpus or model no longer produces, then embeds new chunks in batches of 32. Why: idempotent runs, and a model or chunking change never leaves stale or incompatible vectors citable.
- 2026-11-21, David: The regulation PDFs ship as server resources (`ai/regulations`), and ingestion runs in the background at startup when `DORAI_DB_URL` is set (`DORAI_AI_INGEST_ON_STARTUP=false` to skip). Why: the server answers at once and a failed ingestion never stops it.
- 2026-11-21, David: AI provider from `DORAI_AI_PROVIDER` (`fake` default, `openai` with `DORAI_AI_OPENAI_KEY`); the fake embedder hashes words into 1536 dimensions. Why: nobody needs a key to work and tests stay offline.
- 2026-11-21, David: Footnotes are recognised by their Official Journal reference with ELI link, or by breaking the numbering. Why: CIR footnote lists restart at (1) and looked like list items; quoted references in the DORA text have no ELI and stay.
- 2026-11-21, David (lane exception, agreed for speed): the RAG branch adds PDFBox, pgvector and Koog embeddings to the server build and hooks regulation search into `servicesFromEnv`; it uses Ignjat's `Db` and takes migration V2. Why: ingestion and search could not wait; Ignjat reviews.
- 2026-11-21, David: Ingestion refuses an empty chunk list and keeps the stored chunks. Why: an empty corpus means reading or chunking broke, and wiping the table would leave search with nothing to cite.
- 2026-11-21, Matija: Implement the full assigned frontend with both light and dark themes. Why: both appearances and all frontend features are required.

- 2026-11-21, Ignjat: On the first start of an empty install the server creates the admin (`DORAI_ADMIN_USERNAME`, default admin) with a random temporary password and an invite, and logs both once. Why: no password in files, and the admin goes through the same forced password change as everyone.
- 2026-11-21, Ignjat: Refresh tokens are opaque, stored as SHA-256 hashes, single use and rotated in families; reusing a spent token revokes its family. Why: an admin can end a session at once, and a stolen copy is detected the first time both are used.
- 2026-11-21, Ignjat: Auth is on whenever the server has a database and off on fixtures in memory. Why: every real install has a database; app and test work needs no login.
- 2026-11-21, Ignjat: Access tokens are HMAC-signed JWTs valid 15 minutes; sessions last 30 days; invites 72 hours; passwords Argon2id (19 MiB, 2 iterations) with at least 12 characters. Why: common safe defaults; the parameters travel inside each hash, so they can be raised later.
- 2026-11-21, Ignjat: One access plugin applies the role table of plan section 4; reads need viewer, unknown writes need admin. Added `POST /admin/users/{username}/disable`. Why: one place to review who may do what, and new write routes are closed by default.
- 2026-11-21, Ignjat: The server generates its self-signed certificate on first start with Ktor's certificate builder and keeps it in the `server-data` volume. Why: the apps pin its fingerprint from the invite link, so no certificate authority is needed.
- 2026-11-21, Ignjat: The health check stays on plain HTTP 8080, published on 127.0.0.1 only; the apps use HTTPS 8443. Why: Docker and curl on the host need no certificate, and nothing outside the host can reach the plain port.
- 2026-11-21, Ignjat: Every API call checks that its session is still live and the user not disabled (one indexed lookup); the access token carries its session id. Added `POST /admin/users/{username}/revoke` to sign a user out everywhere. Why: disabling, logout, a password change or a revoke end access at once instead of within 15 minutes.
- 2026-11-21, Ignjat: `dorai check` reads the register from a JSON file (the `GET /api/register` format) and runs the shared rules offline; a server mode can come later. Why: any CI runner can use it, with no network path or CI login to the firm's server.
- 2026-11-21, Ignjat: `dorai check` prints text, Markdown (the PR comment) or JSON and exits 0 clean, 1 on High findings, 2 on bad input. Why: the behaviour CI users already know from the earlier scanner.
- 2026-11-21, Ignjat: The GitHub Action is a composite action in this repo (`action.yml`) that builds the CLI from its own source and keeps one sticky PR comment. Why: firms reuse it with one `uses:` line, and it needs no release to work.
- 2026-11-21, Ignjat: Failed logins are counted per username in memory: five within 15 minutes refuse that username for 15 minutes, the right password too; an admin revoke lifts it. Redeem, login and password change also allow 10 calls per minute per address (Ktor RateLimit). Why: stops guessing one account from many addresses and many accounts from one, without a database write per failure; one server per install, so memory is enough.
- 2026-11-21, David: The AI services talk to a small `ChatModel` interface in `dorai.server.ai.chat`, with a Koog implementation and a fake that answers from keyword rules and cites the supplied evidence. Why: tests and the default setup run the whole prompt, parse and citation path offline, and Koog API changes stay in one class.
- 2026-11-21, David: The Koog chat model uses `executeStructured` with the JSON schema of each reply type and no fixing parser; the services check the reply (cited ids must come from the evidence, closed service-type list, confidence 0 to 1) and retry once on a bad reply, never on an outage. Why: Koog's default fixing prompt fills in missing fields without seeing the evidence, which would be a made-up answer; native schema mode already prevents most broken JSON, and only our code decides when the model is asked again.
- 2026-11-21, David: Default chat model `gpt-4.1-mini`, changeable with `DORAI_AI_CHAT_MODEL`. Why: cheap, reliable at JSON-only answers and closed lists, no reasoning tokens.
- 2026-11-21, David: Every AI service searches the regulation first; no passage above the threshold is "insufficient evidence" without a model call. "Unknown" from the classifier or suggester is also "insufficient evidence", and a search or model outage is `AiAnswer.Failed`. Why: an uncited or made-up answer can never reach a reviewer, and an outage is never stored as a suggestion.
- 2026-11-21, David: Task instructions live in `server/src/main/resources/ai/prompts`; resource names, tags, findings and evidence go in a separate user message marked as untrusted data. Why: prompts are easy to review, and cloud data cannot act as instructions.
- 2026-11-21, David (lane exception, agreed): `servicesFromEnv` calls `Services.withAi(database, config)` from `AiSetup.kt`, which swaps the stand-in AI for the real services when `DORAI_DB_URL` is set. Why: the services need wiring; it is one line in `Application.kt` for Ignjat to review.
- 2026-11-21, David: The search threshold defaults to 0.25 for the fake provider and stays 0.40 for `openai`; `DORAI_AI_MIN_SIMILARITY` overrides both. Why: the word-hashing fake ranks the right passage first but scores about 0.3, so at 0.40 the offline setup never suggested a business function.
- 2026-11-21, David: The report drafter returns a summary plus one note per rule finding (ruleId, resourceAddress, one sentence), in the rules' order; a draft that adds, drops or repeats a finding is rejected. Missing register data ("gaps") stays out for now. Why: the PDF needs the finding sentences, and naming each finding lets the check prove the AI changed none.
- 2026-11-21, David (lane exception, agreed): `ReportDrafter` in `dorai.server.core` returns `AiAnswer<DraftText>` (summary plus `FindingNote`s) and the `NoAi` stand-in follows. Why: the interface had to carry the finding notes; Ignjat reviews it in the PR.
- 2026-11-21, David: `OpenAiEmbedder` sends one Koog embedding request per text, one after another. Why: Koog 1.3 throws "Batch embedding is not supported" for a list of texts with OpenAI, so ingestion and every search failed with provider `openai`; one request per text keeps the call inside Koog, and ingestion runs once in the background.
- 2026-11-21, David: `DORAI_AI_MIN_SIMILARITY` must be a number from 0 to 1; anything else stops the server at startup, and an empty value keeps the provider default. Why: a typo or a value above 1 silently left search with no evidence, so every AI answer became "insufficient evidence".
- 2026-11-21, Ignjat: The server image sets `JAVA_OPTS=-XX:MaxRAMPercentage=75`, and every pull request builds the image for linux/amd64 without pushing. Why: the heap follows the container limit, and a broken Dockerfile shows up on the PR instead of on the release tag.
- 2026-11-21, Matija: Implement the PDF report using the selected OpenPDF library and bundled Host Grotesk fonts. Include register validation even on errors, complete single-currency contract totals, unchanged rule findings, field sources and cited AI draft text; omit unconfirmed field values and keep export available when drafting fails.

The server comes from the invite email later; until then the app uses the development address (`localhost:8080`, emulator `10.0.2.2:8080`). Why: users connect only through the admin's invite, never by typing an address.
- 2026-11-21, Luka: The login page always logs in for real through `DoraiApi.login`; there is no way past it on a server without auth. Why: the app behaves the same in development as for users, and local testing uses the database with the admin's temporary password.

- 2026-11-21, Luka: The workspace shows the user, role and a Log out button; tokens stay in memory (`MemoryTokenStore`) until secure storage in step 6. Why: login can be tested again without a restart, and the full session handling comes with step 5.
- 2026-11-21, Ignjat: Every OpenAI call (chat and embeddings) goes through Koog's `RetryingLLMClient` (`openAiClient` in `dorai.server.ai`): a 429, a 5xx or a dropped connection is sent again, up to 6 attempts, waiting what the server names ("retry after 15 seconds") or 2, 4, 8, 16 and 30 seconds; other errors fail at once. Why: the live run on Azure OpenAI (50K tokens per minute) hit 429 during ingestion and search, so ingestion stopped halfway and a rate limit showed up as "insufficient evidence". Koog's own retry instead of ours: it already reads the wait from the error and stops on cancellation.
- 2026-11-21, Ignjat: Built Cloud inventory (scan, resource list) and AI review (suggestions with citations, accept, reject) in `dorai.app.inventory` and `dorai.app.review`, linked through `ServerSources` like the other sections, so the whole app runs end to end on live data. Inventory shows a scanned value as scanned; where the scan found none, an accepted suggestion shows as human-confirmed and a pending one as ai-suggested. Why: linking every section was the integration goal; Luka owns these packages and can rework the screens.
- 2026-11-21, Ignjat: `scripts/dev-local.sh` runs the whole app locally with no cloud keys: its own Postgres container on 127.0.0.1:5433, the server with demo data and the fake AI on 8080, then the desktop app; on a first start it sets the admin password to `dorai-local-dev` through the normal password change. Why: teammates without Azure or OpenAI keys need one command to work against a real server with login; the fixed password passes the real policy (12+ characters, not the username), so the server is not weakened.
- 2026-11-21, Ignjat: RoI full compliance is built on one branch, `ignjat/extra-compliance`, across all lanes (AI, export, app screens included), as one commit per phase pushed to that branch. Why: one reviewable line of work for the whole RoI; David, Matija and Luka review their packages on the branch before it merges.
- 2026-11-21, Ignjat: RoI scope is group-ready: the model holds other group entities, branches and intra-group links as template rows, while forms and auto-filling target a single entity first. Why: the model shape is cheap now and a second migration later is not.
- 2026-11-21, Ignjat: RoI columns beyond the named fields are kept per item as `roi: Map<column code, RegisterField>` (jsonb in PostgreSQL, migration V4), and templates with no item of their own as `Register.rows[template]`. Values stay text; the readiness check parses dates, numbers and codes. Why: one shape for all 98 columns, provenance on every value, and the exporter, checks and forms all read one spec table (`dorai.shared.roi.RoiSpec`) instead of 60 hand-written fields.
- 2026-11-21, Ignjat: `RoiTables` builds the 15 templates from the register and the last scan at read time; scan-derived values (locations, storage, cost) are not stored. - 2026-11-21, Ignjat: B_02.02 gets one row per storage or processing country (CIR B_02.02.0150 and 0160 ask for additional rows); the i-th row pairs the i-th storage country with the i-th processing country. Why: every country is reported once without a cross product of rows.
- 2026-11-21, Ignjat: Closed lists are stored as the CIR option keys ("1", "S17", "true"/"false" for yes or no); the export maps them to EBA taxonomy codes in one table. Why: the register stays readable against the CIR, and a taxonomy release only changes that table.

- 2026-11-21, Ignjat: A provider that is its own ultimate parent sets B_05.01.0110 to its own code; the export leaves 0110 and 0120 blank. Why: the CIR asks for the parent only when the provider is not the ultimate parent, and the register needs a way to say "it is".
- 2026-11-21, Ignjat: The Art. 12, 28(8), 29, 28(3) and security checks are warnings in the RoI view, never errors, and only reviewer-confirmed values count. - 2026-11-21, Ignjat: Defender for Cloud and Security Hub findings are stored on each resource as data (migration V5, `alerts`), and a deterministic rule decides what to raise. Why: "rules decide findings": the tools report, DORAi's rule decides.
- 2026-11-21, Ignjat: The AI drafts only four judgement columns (B_02.02.0170, B_02.02.0180, B_06.01.0020, B_07.01.0050), as option keys with a citation or "unknown", during a full suggestion run. Why: these cannot be scanned; everything else is scanned, derived or typed.
- 2026-11-21, Ignjat: The app edits one RoI cell at a time through `PUT /register/values/{item}/{column}` (entity cells under `/register/entity/values`, admin). Scanned and derived cells are read-only there. Why: one generic form for 15 templates, and a scanned value changes at its source.
- 2026-11-21, Ignjat: The taxonomy check runs Arelle in CI on the FinPay package (`scripts/validate-roi.sh`, Gradle task `roiSample`) and is skipped until the repository variable `EBA_TAXONOMY_URL` is set. - 2026-11-21, Ignjat: The DORA RoI is built against EBA reporting framework 4.0 errata 5 (DORA module 1.1.0, `fws/dora/4.0/mod/dora.json`), not 4.3. Why: the 4.3 package holds no DORA module; 4.0 errata 5 is the one that applies from 2025-03-31.
- 2026-11-21, Ignjat: Column codes follow the taxonomy where it differs from the CIR text: B_06.01 is numbered 0010 to 0100 (criticality at 0050), and the Link columns B_02.03.0030, B_03.01.0030 and B_03.03.0031 always report true. Why: the filing is checked against the taxonomy, not the CIR PDF.
- 2026-11-21, Ignjat: Closed lists, countries, currencies and code types are exported as taxonomy members (`eba_ZZ:x791`, `eba_GA:IE`, `eba_qCO:qx2000`), from `TaxonomyCodeLists.kt`, generated by the committed `scripts/taxonomy-codes.py` from the taxonomy files. - 2026-11-21, Ignjat: B_06.01.0020 offers the taxonomy's 131 licensed activities (member codes such as `x28` payment services, `x276` supporting function) instead of the CIR letters a to u. Why: the taxonomy lists activities, not entity types, and only its members are valid.
